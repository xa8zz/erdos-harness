# Unified Gravity 2025 — program operating notes

These notes scope folder-specific deviations from the harness defaults documented in `/CLAUDE.md` and `/docs/writing-prompts.md`. Inheritance: the general harness rules apply unless overridden here.

## Internet allowed — explicit override

Unlike the math-domain programs in this harness (`erdos-872`, `erdos-500`), the unified-gravity-2025 program **explicitly allows and encourages internet / literature use in dispatched primary-researcher prompts**. The peer-reviewed and preprint literature on quantum field theory, gauge theory, BRST cohomology, BPHZ renormalization, Slavnov-Taylor identities, asymptotic safety, higher-derivative gravity, and teleparallel gravity is in scope and should be consulted.

**Why the difference.** Math-research dispatches benefit from no-internet because (i) the open problems have no settled literature to retrieve, and (ii) forum posts and partial prior work contain attractor-state failures the model imports if it can retrieve them. Physics is the opposite: the apparatus needed to evaluate a paper's claim — BRST cohomology, BPHZ subtraction, dimensional regularization, the 't Hooft–Veltman one-loop result, the Goroff–Sagnotti two-loop result, Stelle higher-derivative gravity, the Wess–Zumino anomaly consistency condition, asymptotic-safety literature, etc. — is settled, refereed, and the right tool for the job. Asking a fresh-thread model to re-derive textbook material every dispatch is wasteful and produces shallower attempts.

**Implementation.** Researcher-prompt headers in this folder open with an explicit "you may use the internet" line and require the model to cite specific works (author, year, title, arXiv/DOI when possible) for any non-trivial result, lemma, or counterexample. The no-search rule from `templates/solution-attempt.md` is **not** used here.

## Curated references library — build over time

Each researcher response cites works. After every round, extract the citations into `unified-gravity-2025/references.md` so future dispatches can pre-load the relevant literature instead of asking the model to re-search the same ground.

Bibliography entry format:

```markdown
- **[Author Year]** Full title. *Journal / arXiv:XXXX.XXXXX / DOI*. First cited in R<NN>; used for: <one-line note on the result invoked>.
```

When composing later prompts, include only the entries directly load-bearing for that dispatch (not the entire bibliography — that would bloat the prompt). The bibliography is the curator's reference; the prompt cherry-picks.

If a paper turns out to be load-bearing across many rounds, consider extracting its key result(s) into a `Known progress` block of the prompt itself with the citation, rather than asking the model to re-fetch and re-summarize.

## Verification stack

The formal-proof layer (Aristotle / Lean) is not load-bearing here — mathlib has effectively no formalized QFT, so gauge-fixing, BRST cohomology, Feynman-rule renormalization, and BPHZ subtraction cannot be formally verified via the usual harness path. Verification relies on:

1. **Cross-family informal verifiers** (Pro / DeepThink / Gemini / Claude tabs) for conceptual claims (BRST closure logic, power-counting arguments, ghost-spectrum reasoning, RG consistency).
2. **Symbolic computer algebra** for the calculational sub-claims — Cadabra (designed for field-theory index notation and gauge theories), FORM (Feynman-diagram symbolic computation), xAct / xTensor / xPert (Mathematica tensor calculus for GR), FeynCalc / FeynArts / FormCalc (amplitude calculation). These are not proof assistants but rigorous symbolic computation; they catch sign errors, missed terms, gauge-fixing inconsistencies, and broken Slavnov-Taylor identities.
3. **Adversarial cross-checks against the existing critique landscape** in the QG community. Where multiple expert critiques exist, the prompt's `What does not work` section should reflect them with specific failure mechanisms.

Convergence across (1) and an explicit (2) calculation is the strongest available "promote to Established" signal for this program.

- `references.md` — curated bibliography.
- `state_compiled.md` — generated by `scripts/compile_rounds.py`; do not hand-edit.
- No `current_state.md` or `canonical-prompt.md` — deprecated for new folders; the action graph + compiled view is authoritative.
